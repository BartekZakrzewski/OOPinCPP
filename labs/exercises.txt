1. Implement in C language stack of integers. Provide the following functionality:

void init(Stack* s)
void destroy(Stack* s)
void push(Stack* s, int element)
int pop(Stack* s)
bool isEmpty(const Stack* s)
Allocate the memory dynamically. When stack capacity is not sufficient any more due to the push function calls increment the stack size. Propose reasonable strategy for how the stack size grows. Growing by one cell is not allowed (it causes memory reallocation with every push operation). Use valgrind to verify there are no memory leaks.

Handle all possible errors (e.g. failure in memory allocation or calling the pop function when the stack is empty).

Carefully test the implemented functionality. Think about possible use cases and propose a few test cases.

Split the program into Stack.h, Stack.c and TestStack.c files.

Tip 1
In C language, depending on the compiler version, it may be necessary to include the stdbool.h header file to use a bool type.

Tip 2
In C language it is more convenient to define structures using the typedef keyword:

typedef struct {
    // Put member variables here.
} Stack;
Then you do not need to specify the struct keyword later in the program. Structure types defined without the typedef keyword must be later used in the program with the struct keyword. For example the declaration of the init function becomes longer as follows:

void init(struct Stack* s)
Tip 3
In C and C++ language, to prevent the content of a header file from being included more than once in the same compilation unit, you can use the #pragma once preprocessor directive (it is not standard, but it is recognized by many compilers, including gcc and Microsoft Visual C++):

// MyFile.h
#pragma once
// Put code here.
It is a convenient replacement for the traditional and standard solution, which is to insert the include guards:

// MyFile.h
#ifndef MYFILE_H
#define MYFILE_H
// Put code here.
#endif 
To check if it works, you can experiment and include Stack.h twice in one of your .c files:

#include "Stack.h"
#include "Stack.h"

6. Write the class representing a matrix. Use reference counting in the implementation. Implement the following functionality:

copy constructor,
assignment operator,
stream insertion operator <<,
arithmetic operators: + - * += -= *=,
comparison operators: == !=,
ability to read matrix from input file stream,
single element access - you can overload the () operator, so that m(2, 3) means element placed in row 2, column 3 of the matrix object m. You are required to distinguish between the reading and writing operations. If you present a program which treats every single element access as a write operation then the grade is decreased by 20%.
You are not allowed to use containers from the C++ standard library except the std::string class. To store matrix elements in the memory use the memory allocation technique which you know from this PDSC lecture (check slides entitled Two-Dimensional Arrays). Use new and delete operators instead of malloc and free functions.

Error handling:

in case of an error throw an exception,
distinguish different types of errors by throwing exceptions of different types,
provide your own classes to represent errors (one class per one type of errors).
Carefully test the implemented functionality. Test whether reference counting works properly. Test throwing the exceptions.

Split the program into Matrix.h, Matrix.cpp and TestMatrix.cpp files (you can extract more files if you wish).

It is possible to present a simplified program where reference counting is not implemented. In this case the maximal grade is 60%.

8. Write your own version of the popular computer game Pac-Man. Use the Qt library.

Implement the following functionality:

one graphic object - representing the player - is controlled by the keyboard,
four graphic objects - representing the enemies - are controlled automatically by the computer and each enemy has different behaviour,
there are two kinds of objects to be collected by the player:
simple objects increasing the score of the player,
special objects increasing the score of the player (by the value greater than in case of simple objects) and modifying the status of the player in the following way: when the special object has been collected, the player can catch the enemies for a certain period of time. Otherwise the enemies can catch the player.
Propose appropriate class hierarchy. For example it is recommended that the enemies are stored in one container (consider using virtual functions).
